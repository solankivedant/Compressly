## 2. Layering rules

| Layer | Lives in | May import | Must not |
| --- | --- | --- | --- |
| UI | `lib/ui/` | `lib/core/**` public APIs, `lib/app/theme.dart`, l10n | Call Pigeon or SDKs directly; create services |
| App shell | `lib/app/` | everything in `lib/` | Contain business rules |
| Domain (pure Dart) | `lib/core/domain/` | Dart SDK only | Flutter, SDKs, Pigeon |
| Services | `lib/core/services/` | SDK packages, generated Pigeon code, domain | UI widgets |
| Bridge (native side) | `android/.../bridge/` | engine packages | Business rules (delegate to engine) |
| Engine (native) | `android/.../{scan,encode,quality,library,queue,schedule,data,entitlement}` | Android SDK, Media3, Room, WorkManager | Flutter classes |

Every SDK sits behind a Dart interface in `lib/core/services/` with a `Fake` implementation used in tests and in `flutter run --dart-define=FAKE_SERVICES=true` (UI work on a desktop or emulator without media).

## 4. Composition and state

- `bootstrap()` creates every service once, in this order: logger → Remote Config defaults → Firebase (consent-gated) → EngineService → BillingService → AdService → UiPrefs. Only engine and prefs are awaited before the first frame (NFR-13).
- `AppScope` exposes services to widgets. Services extend `ChangeNotifier`; widgets use `ListenableBuilder`.
- Flutter holds **no authoritative engine state**. On resume, the UI re-reads status, totals and the queue from the engine. Live updates arrive through `EngineEvents` while the Flutter engine is attached; if it isn't, nothing is lost because Room is the source of truth.

## 5. Pigeon contract (`pigeons/engine_api.dart`)

| Call | Returns | Purpose |

| `setHoldingPeriod(jobIds, days)` | void | FR-15 |
| `setSettings(EngineSettings)` | void | preset, conditions, exclusions, auto on/off |
| `setEntitlement(EntitlementDto)` | void | plan, expiresAt, bonusBytes; pushed after every RevenueCat change |
| `setRemoteTuning(TuningDto)` | void | presets, deny list, thresholds (FR-35) |

### 5.2 Flutter API (Kotlin → Dart)

| Call | Purpose |
| --- | --- |
| `onJobProgress(jobId, percent, state)` | Live progress (throttled to ≤ 4 per second) |
| `onJobResult(ResultDto)` | Final before/after/SSIM |
| `onQueueChanged()` | UI should re-read the queue |
| `onConditionsChanged(ConditionsDto)` | charging, battery, thermal, free space |

Rules: DTOs only (no platform types). Every host call returns quickly; long work happens in the engine's coroutine scope and reports through events. Errors cross the bridge as `FlutterError(code, message)` with codes from a fixed list (`permission_denied`, `no_space`, `busy`, `not_found`, `internal`). **Never put file paths or names in error messages that might reach analytics.**

## 6. Job state machine

```
            enqueue
               │
               ▼
   ┌──────► QUEUED ──────────────┐ cancel
   │           │ conditions ok   ▼
   │           ▼              CANCELLED
   │       ENCODING ──── fail ──► (attempt < 2 ? QUEUED : FAILED)
   │           │ temp file complete
   │           ▼
   │       VERIFYING ── gate fails ──► retry at +25% (QUEUED, attempt 2) or SKIPPED("not worth it")
   │           │ gate passes
   │           ▼
   │        SAVING  (MediaStore row with IS_PENDING=1, metadata copied, then IS_PENDING=0)
   │           │
   │           ▼
   │        READY   (both files exist; original listed for review; allowance counted)
   │           │ user approves delete ────────────────► DONE (freed)
   │           │ user keeps original ─────────────────► REVERTED (output removed)
   └── interrupted (kill/reboot/timeout): recovery rules below
```

The DPR listed five states; **SAVING** and the terminal states are added for crash safety.

**Persistence rule:** a state is written to Room *before* the side-effect that depends on it starts, and the next state is written only after the side-effect is confirmed.

**Recovery on app start / worker start (NFR-02, FR-38):**

| Found in state | Action |
| --- | --- |
| ENCODING | Delete temp file, back to QUEUED (attempt unchanged) |
| VERIFYING | If temp file exists and is complete, re-verify; else QUEUED |
| SAVING | If the pending MediaStore row exists: delete it. Back to VERIFYING with the temp file, or QUEUED if the temp file is gone |
| READY / DONE | Nothing |
| Any | Delete orphaned files in the temp dir not referenced by a job |

The original is never opened for writing, at any state.

## 7. Safety design (the non-negotiables)

1. **Read-only originals.** The engine opens originals with `"r"` mode only. No code path writes to an original URI.
2. **Delete only through the system.** Deleting originals uses `MediaStore.createDeleteRequest()` (API 30+) or the `RecoverableSecurityException` flow (API 29). The user always sees the system dialog. There is no silent delete path.
3. **Delete only READY jobs.** `OriginalsRequester` accepts job ids, re-checks each is READY, the output URI exists, its size matches the recorded size, and the output can be opened and probed (duration/dimensions). Any failure removes that item from the batch.
4. **Free space first.** Before ENCODING: free space ≥ 1.2× source size (NFR-07). Before SAVING: re-check.
5. **One job at a time** (NFR-15).
6. **Temp in app-private storage** (`context.cacheDir/jobs/`), deleted after each job and in recovery (NFR-16).
7. **Kill switch.** Remote Config `engine_enabled=false` stops new jobs. `engine_delete_enabled=false` disables the delete button and shows "Review later".
8. **Safety suite gates every engine change** (`tool/safety/`, RISK R1).

## 8. Engine design

### 8.1 Scanner
Queries `MediaStore.Video` and `MediaStore.Images` (`MediaStore.VOLUME_EXTERNAL`), paging by `_ID`. Probes codec, bitrate and dimensions with `MediaExtractor`/`MediaMetadataRetriever` (video) and `ExifInterface` + `BitmapFactory.Options.inJustDecodeBounds` (photos), lazily: metadata from MediaStore first, deep probe only for candidates. Results go to `media_item`. `EligibilityRules` (pure Kotlin) applies FR-03, FR-07 and FR-36. `SavingsEstimator` predicts output size = target bitrate × duration + audio.

### 8.2 Video encoder
Media3 `Transformer` with `setVideoMimeType(MimeTypes.VIDEO_H265)`, a `DefaultEncoderFactory` with `VideoEncoderSettings` bitrate from `PresetResolver`, audio passthrough, HDR mode keep-HDR (skip if not supported, FR-07). Output: app-private temp MP4 via the Media3 in-app muxer so location, creation time and orientation metadata can be written. Progress polled with `getProgress()` and throttled.

### 8.3 Photo encoder
Safe mode: JNI call into libjpeg-turbo transform (optimise + progressive, copy all markers) → byte-identical pixels; verified by decoding both and comparing. Max savings: decode → `HeifWriter` (quality 85–90) → copy EXIF via `ExifInterface`.

### 8.4 Quality gate
`FrameSampler` picks 10–20 timestamps (more where `MediaExtractor` sync-frame density suggests motion) and extracts frames from source and output at the same timestamps, scaled to ≤ 960 px wide. `Ssim` computes luma SSIM (8×8 window) per frame; PSNR logged too. Accept rules: FR-09, FR-10, FR-37.

### 8.5 Library writer
Inserts into `MediaStore` with `RELATIVE_PATH` = original's folder, `DISPLAY_NAME` = original base name + `.mp4`/`.heic` (MediaStore resolves clashes), `IS_PENDING=1`, `DATE_TAKEN` = original's. Copies bytes from temp, writes metadata, sets `IS_PENDING=0`, then re-reads the row to confirm. Records a Compressly marker (`XMP`/MP4 user-data tag `cmpr=1`) so FR-36 skips our own outputs.

### 8.6 Scheduler and background
- **Manual "Compress now":** starts `CompressionService` (FGS) immediately.
- **Auto (Pro):** `NewMediaWorker` uses a WorkManager content-URI trigger on Images and Video. It enqueues eligible new items. `QueueWorker` has `requiresCharging` (if set) and `batteryNotLow`, and starts the FGS to process the queue.
- **FGS type:** `mediaProcessing` on API 35+, `dataSync` on API 29–34. On `onTimeout()`: finish or abandon the current file safely (recovery rules), persist, stop, and reschedule.
- **RunConditions** listens to battery, charging, `PowerManager` thermal status and free space. Pauses at moderate thermal (NFR-05). Resume needs 2 minutes below the threshold.

### 8.7 Allowance guard
Pure Kotlin. Inputs: entitlement cache, bytes saved this calendar month (sum over READY/DONE results), bonus bytes. A job starts only if the user is Pro or allowance remaining > 0. Auto-compress requires Pro with an unexpired cache. Flutter re-pushes the entitlement on every launch, and the cache expires 3 days after `expiresAt` for offline grace.

## 9. Data design (Room, `EngineDatabase`)

| Table | Key columns |
| --- | --- |
| `media_item` | id (MediaStore _ID), uri, type, mime, codec, width, height, fps, bitrate, size, duration_ms, date_taken, bucket_id, is_hdr, is_ours, excluded, estimated_after, scanned_at |
| `job` | id, media_id, preset, mode, state, attempt, temp_path, output_uri, output_size, hold_until, created_at, updated_at, last_error_code |
| `result` | job_id, size_before, size_after, ssim_mean, ssim_min, psnr_mean, encoder (hevc/avc/jpeg/heic), duration_ms, outcome |
| `engine_settings` | key, value |
| `entitlement_cache` | plan, expires_at, bonus_bytes, bonus_month, ads_today, ads_day |
| `tuning` | key, value (Remote Config snapshot) |

Every schema change ships with a Room migration and a migration test. No destructive migrations ever.

### Remote Config keys (defaults bundled)

`preset_video_table` (JSON), `preset_ssim_thresholds`, `engine_enabled`, `engine_delete_enabled`, `engine_device_denylist` (JSON: brand/model/chipset → `hevc_off` | `engine_off`), `free_allowance_bytes` (2 GB), `ads_bonus_bytes` (1 GB), `ads_max_per_day` (5), `paywall_variant`, `price_test_variant`.
Fetched in the background, **activated on next launch**, and pushed to native with `setRemoteTuning`.

## 10. Monetisation design

- **BillingService** wraps RevenueCat: offerings `default` (monthly, yearly, lifetime), entitlement `pro`. Displayed prices always come from the store product. On every customer-info update → `setEntitlement` to native.
- **AdService**: UMP consent at first paywall view (not at launch), then preload one rewarded ad. Reward is granted only on `onUserEarnedReward` → `setEntitlement` with new bonus. Never shown while a job is running in the foreground.

## 11. Analytics (consent-gated)

Events: `scan_completed(items, eligible, est_gb_bucket)`, `compress_started(count, preset)`, `job_result(outcome, saving_pct_bucket, ssim_bucket, encoder)`, `originals_deleted(count, gb_bucket)`, `paywall_shown(reason)`, `purchase(plan)`, `ad_reward`, `battery_guide_shown(brand)`, `thermal_pause`. **Buckets, not exact values; never file names, paths, dates taken or locations.**

## 12. Error handling and resilience

- Every async SDK call is wrapped; ads/billing/Firebase failures never block compression or the UI.
- Engine errors map to `last_error_code`; the UI shows a plain-words reason and "Try again".
- Crashlytics gets stack traces with no custom keys containing media data.
- An encoder crash on a specific device model is caught, recorded, and after 2 crashes for the same model the engine auto-falls back to H.264 (and reports `encoder_fallback`).

## 13. Security and privacy

- No exported components except `MainActivity`. FGS not exported.
- Temp files app-private. Android backup via `dataExtractionRules` includes `shared_prefs` only. The engine database and cache dir are excluded, because a restored job table could point at originals that no longer match. Purchases come back through RevenueCat restore.
- R8 minify + resource shrink for release.
- Logging helper strips URIs to ids; never logs display names.

## 16. Extension points

- **iOS (v2):** a Swift implementation of the same Pigeon host API; the Dart side doesn't change.
- **Duplicates (v1):** new `dupes/` engine package + `listDuplicateGroups` host call.
- **Content-aware bitrate (v2):** replace `PresetResolver` with a strategy interface.
